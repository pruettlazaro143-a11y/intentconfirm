## 发现并修复

1. **修改后的值沿用旧确认和旧证据。** 复现：goal从学习练习改成作文后仍为confirmed，confirmation仍引用旧句。修改证据未存入输出。修订：直接修改变为candidate并清除旧确认；新证据进入当前项目，旧项目值与修改事件留在change_log。
2. **同批上下游修改保留过期确认。** 原遍历以全部改动ID作为seen，互相依赖的改动根被跳过。修订：分离遍历集合与后代集合；所有直接修改均解除旧确认，仍活跃的传递下游标stale。
3. **未校验原始输入。** 只检查输出；status=broken可在补丁中改为candidate后通过。修订：处理前校验完整原记录，禁止修复后掩盖无效输入。
4. **新回答无法原子加入。** 旧工具只允许引用原记录已有来源，迫使调用方先编辑旧文件。修订：支持sources+patches的JSON对象，一次加入新用户原话与修改；旧source禁止覆盖。
5. **强制写出可改写原文件。** 用输出硬链接指向输入并传--force，原CLI返回0且原内容被改变。修订：取消覆盖模式，以独占创建拒绝已有路径、软链接与硬链接别名。
6. **空/无变化补丁抹掉批准。** 修订后完全无变化时保持原记录，避免无意义重复确认。禁止补丁直接写confirmed/stated；采用修改后候选需实际用户响应另行记录。

原测试中多次用“改成作文练习”作为“展示作品或业务”的依据。检查器不进行语义蕴含判断，但测试示例不应诱导错误使用；已使样例值与引文一致。引文存在仍不保证模型理解正确。
