# Bob 版本审阅与修复记录

审阅日期：2026-09-26。输入：用户上传的 intentconfirm.zip。执行：Codex。

## 结论

复跑 Bob 提供的测试确为 21/21 通过；但若干测试断言沿用了有问题的行为，例如把 AI 作用回答后从问题目录删除、把“不要登录”扩成“不做登录与支付”。单独的通过数量不能说明交互和需求理解正确。

本次在 Bob 版本上修复了以下可复现问题，并添加有针对性的回归检查。

| 问题 | 原行为 | 本版处理 |
| --- | --- | --- |
| AI 未知绕过 | ai_role 只要有答案就从目录消失，unknown 也能移除阻塞 | 适用性与回答状态分离，未知仍阻止确认 |
| AI 作用导出丢失 | 已回答 ai_role 不再进入 rows/specification | 保留于确认单、修改入口和两个导出格式 |
| 修改已确认答案无效 | nextQuestions 排除已确认项，编辑按钮找不到对应卡片 | 编辑显式指定当前批次，实际浏览器验证 |
| 无依据扩大约束 | 不要登录被写成不要登录与支付 | 保留原文字面条件，单独提供登录与支付选项 |
| 口语/作文混用 | 练习与反馈一律触发录音问题 | 只有确认的口语/语音功能触发输入方式 |
| 未知变更未失效 | setAnswer 的 unknown 分支提前返回 | 未知转换也经过依赖更新 |
| 上下文失效遗漏 | 录音、AI 作用、作品内容不在相关依赖链 | 补充依赖与重激活规则，保护历史快照 |
| 候选确认丢来源 | 普通选择覆盖候选的 evidence | 专门确认入口保留原文依据和候选编号 |
| 覆盖提示失真 | 有一个关键词即 covered；无候选时面板提前返回 | 所有识别均标为 partial/unknown，零信号也显示限制 |
| 多候选被首项覆盖 | applyFacts 优先采用第一条目标 | 冲突候选不预选，等待用户明确优先项或组合 |
| 需求编号漂移 | 按当时活跃问题数组顺序编号 | 固定字段到 REQ 编号映射 |
| 旧状态沿用错误确认 | 同一存储键直接恢复旧规则结果 | 保留选择与历史，旧当前版本降为待重新核对 |

另补充字面预算/时间候选，修复界面过时说明。旧的固定分页 DOM 冒烟脚本已被真实浏览器回归脚本替代。

## 测试调整的原因

保留原测试主体，修正不符合产品目标的预期：AI 作用应留在规格；不增加支付限制；录音只适用于明确口语；目标变更后的相关 AI 作用也需核对。追加 12 个回归案例，总计 33 个。
